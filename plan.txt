1. Core thesis

- Baseline paper: a minimum viable, falsifiable CMS-style study of sequential PDF transfer from `ttbar` to Higgs, with the latent transfer state fixed to rank 1 throughout the baseline claim.
- Central question: can one physically interpretable gluon-PDF mode, learned from top-pair data, be propagated into one Higgs observable with predictive value that survives a realistic nuisance partition?
- Frozen baseline mapping:
- top control observable: normalized `m_tt`;
- Higgs target observable: normalized `|y_H|` in `ggF`;
- mandatory early gate: compare absolute vs normalized `m_tt` before the main closure study;
- optional refinement only if overlap is too weak: one minimal `|y_tt|` split.
- Scientific stance:
- do not silently widen the latent state if rank 1 struggles;
- do not mix "geometric overlap exists" with "rank-1 sequential transfer is sufficient";
- treat failure modes as publishable boundaries on top-to-Higgs transfer.

2. One explicit transferable gluon-PDF subspace

- Define one shared latent coefficient `z` representing a rank-1 gluon-shape deformation supported in the overlapping `x-Q^2` region probed by top and Higgs.
- Operational extraction:
- build PDF-response matrices `R_t` and `R_H` using replicas or Hessian directions in a common PDF basis;
- whiten both observable spaces by their non-PDF covariance so bin scales and nuisance-dominated directions do not define the latent mode by accident;
- extract the leading shared direction from the whitened cross-response using SVD or an equivalent generalized eigenproblem;
- map the resulting observable-space mode back into PDF space and document its `x` support, sign structure, and scale range.
- Required interpretation products:
- one response-geometry plot showing the leading shared mode in top and Higgs spaces;
- one table linking each `m_tt` and `|y_H|` bin to its dominant `x` support and overlap band;
- one statement of how much prior Higgs PDF variance this single mode can in principle control.

3. Early geometry gate: absolute vs normalized `m_tt`

- This is a front-loaded go/no-go gate, not a late robustness appendix.
- Purpose: decide early whether the normalized `m_tt` baseline preserves the Higgs-relevant shared shape information, or whether normalization discards the very mode the program needs.
- Run this before the main identifiability and closure campaign.

- Gate inputs:
- one fixed Higgs target definition: normalized `|y_H|`;
- one fixed PDF basis and whitening prescription;
- top observable version A: absolute `m_tt`;
- top observable version B: normalized `m_tt`.

- Gate procedure:
- extract the leading shared top-Higgs mode using absolute `m_tt`;
- extract the leading shared top-Higgs mode using normalized `m_tt`;
- project the absolute-`m_tt` response into:
- a pure normalization direction;
- a residual shape subspace orthogonal to that normalization direction;
- compare the normalized-spectrum shared mode to the shape-only component of the absolute-spectrum mode, not to the raw absolute mode alone;
- evaluate both comparison metrics on the Higgs side and on the top side after whitening.

- Mandatory gate outputs:
- cosine similarity between Higgs-side response vectors for:
- absolute vs normalized extracted modes;
- normalized extracted mode vs shape-only component of the absolute mode;
- fraction of prior Higgs PDF variance captured by the normalized mode relative to the absolute mode;
- fraction of the absolute-mode discrepancy explained by removing the top normalization component.

- Decision rule:
- `Pass`: high alignment and small loss. The normalized mode stays aligned with the Higgs-relevant shape component of the absolute mode, and most lost sensitivity is attributable to projected-out normalization information. Then the baseline claim may use normalized `m_tt`.
- `Conditional pass`: alignment remains high, but variance capture drops noticeably. Then keep normalized `m_tt` for cleanliness, but downgrade the expected impact to "shape-only transfer with sensitivity loss" and carry that downgrade through the paper.
- `Fail`: the normalized mode rotates away from the absolute-mode shape component or loses too much Higgs-relevant variance for a shape-only interpretation to be credible. Then the baseline program fails on observable choice; do not continue as if the baseline were validated.

- Treatment of thresholds:
- the cosine and variance-fraction numbers are screening tolerances for this early gate unless pilot studies demonstrate they are numerically stable enough to act as hard decision rules;
- if stability is demonstrated, the current working rules are:
- cosine above `0.9`;
- normalized `m_tt` retains at least `80%` of the Higgs variance captured by absolute `m_tt`;
- residual mismatch predominantly explained by the removed normalization direction;
- if that stability is not demonstrated, relabel these values as provisional screening tolerances and make the gate decision from the full geometry summary rather than a single pass/fail line.

- Risk:
- normalization may remove the useful shared mode rather than just rate information.
- Why acceptable:
- this is a cheap early kill test that prevents months of work on an invalid baseline.
- Fallback:
- publish the negative lesson that normalized `m_tt` is too aggressive a compression for sequential Higgs transfer, or move to a deliberately redefined observable in follow-up work rather than mutating the baseline midstream.

4. Operational nuisance partition

- The baseline sequential factorization to test is:
- `p(y_t, y_H | z, c, u_t, u_H) = p(y_t | z, c, u_t) p(y_H | z, c, u_H)`.
- Prior factorization at baseline:
- `p(z, c, u_t, u_H) = p(z) p(c) p(u_t) p(u_H)`.
- The partition must be implemented as an explicit inventory-and-promotion workflow, not just described conceptually.

- Block definitions:
- `u_t`: top-only nuisances. Examples: top reconstruction and unfolding effects, top-only backgrounds, top-only shower/color-reconnection components, category-specific detector effects that do not enter the Higgs measurement.
- `u_H`: Higgs-only nuisances. Examples: Higgs category migrations, Higgs-channel background shapes, Higgs-specific efficiencies and resolutions, channel-specific modeling effects not shared with top.
- `c`: common nuisances that can distort both measurements in a correlated way.

- Internal structure of `c`:
- `c_norm`: global normalization families such as luminosity and shared rate factors;
- `c_pdf,res`: residual shared PDF-theory structure not retained in `z`, such as higher-rank PDF directions and optionally shared `alpha_s`;
- `c_th`: shared perturbative modeling families, especially scale-variation structures that can shape both `ttbar` and `ggF`;
- `c_det`: genuinely shared detector-calibration families that survive the normalized-observable choice, especially JES/JER, `b` tagging, and lepton efficiencies where relevant.

- Nuisance inventory table:
- every nuisance source gets one row with columns:
- nuisance name and physical origin;
- enters top?;
- enters Higgs?;
- acts mostly as normalization, shape, or mixed distortion?;
- survives normalization of the chosen observable?;
- candidate block `u_t`, `u_H`, or `c`;
- if `c`, candidate sub-block `c_norm`, `c_pdf,res`, `c_th`, or `c_det`;
- baseline action: propagate, stress-test only, or exclude;
- reason for that action.

- Promotion workflow for candidate common nuisances:
- Step 1: compute whitened response vectors of each candidate nuisance in top space and Higgs space using the same whitening and binning conventions as for the PDF mode.
- Step 2: form the induced top-Higgs shared distortion for that nuisance family and compare it to the rank-1 PDF shared mode.
- Step 3: record three quantities:
- cosine with the PDF shared mode;
- norm ratio relative to the PDF shared mode on the whitened scale;
- whether the effect is mostly removed by normalization or remains shape-like.
- Step 4: classify the nuisance family using a frozen action rule.

- Frozen action rule:
- `Exclude from propagated state`: nuisance is top-only or Higgs-only by construction, or its shared distortion is negligible after normalization.
- `Stress-test only`: nuisance is genuinely common but has modest overlap with the shared PDF mode and is not large enough to challenge the baseline transfer picture.
- `Promote into propagated c`: nuisance induces a non-negligible aligned shared distortion and therefore cannot be honestly ignored in the sequential latent state.

- Working promotion criterion:
- if the nuisance shared distortion has cosine above `0.7` with the PDF shared mode and whitened norm at least `30%` of that mode, it must be promoted into `c` or the observable definition must be narrowed until it no longer competes materially;
- if pilot studies show these values are not stable against MC noise or binning changes, downgrade them to provisional screening tolerances and require a qualitative-plus-quantitative justification instead of a rigid binary rule.

- Immediate baseline implications:
- `c_norm` is not part of the main normalized-spectrum propagated claim; it re-enters only in the absolute-`m_tt` gate and in explicit stress tests.
- `c_pdf,res` must appear in the richer reference model for the sufficiency audit even if it is omitted from the rank-1 baseline propagation.
- `c_th` and `c_det` start as correlated stress-test families and are promoted only if the response comparison shows they compete materially with the PDF mode.

- Why this belongs in the core program:
- the whole scientific claim is about whether top information transfers through a shared latent structure; if important shared nuisances are left unclassified, the claimed transfer could be a bookkeeping artifact rather than a proton-structure result.

- Risk:
- realistic common detector or theory distortions may rival the PDF mode and force the propagated state to be `(z, c)` rather than `z` alone.
- Why acceptable:
- that is exactly the boundary between a clean PDF-transfer story and a more honest coupled latent-state story.
- Fallback:
- either promote the required nuisance block and weaken the claim accordingly, or publish a no-go statement that rank-1 PDF-only transfer is not valid once shared nuisances are treated seriously.

5. Sufficiency thresholds: decision rules or provisional screening tolerances

- The sufficiency comparison is between:
- rank-1 sequential posterior `p(y_H | p(z | y_t), model_rank1)`;
- richer reference posterior `p(y_H | y_t, model_ref)` built from the same generative setup while retaining the reference shared subspace, including `c_pdf,res` and any promoted common block.

- Continuous metrics to always report:
- bin-wise Higgs posterior mean difference relative to the reference posterior width;
- relative difference in Higgs posterior variance;
- one proper predictive score or log score comparison;
- optional Wasserstein or KL-style shape metric if posterior non-Gaussianity matters.

- Working sufficiency tolerances:
- mean shift within `0.25` of the reference posterior standard deviation in each Higgs bin;
- posterior variance within `10%` relative difference;
- predictive score degraded by no more than `10%`.

- Hardening rule:
- these numbers are not automatically "the" scientific thresholds;
- they become formal decision rules only if pilot ensemble studies show they are stable against finite-replica noise, pseudo-data fluctuations, and mild binning changes;
- otherwise they must be labeled explicitly as provisional screening tolerances used to decide whether rank 1 looks promising enough to study further.

- Stability test required before claiming hard sufficiency:
- run repeated pilot closures under the frozen model with multiple pseudo-data seeds and modest response-matrix perturbations;
- estimate the natural fluctuation band of each approximation metric under repeated draws;
- only elevate a threshold to a decision rule if the threshold sits safely above that fluctuation floor, so "pass/fail" is not dominated by numerical noise.

- If the thresholds survive that stability test:
- use them as frozen decision rules;
- state clearly that "rank-1 sufficient" means the compressed latent state is practically interchangeable with the richer shared model at the stated tolerance.

- If the thresholds do not survive that stability test:
- downgrade all threshold language to provisional screening tolerance;
- remove strong pass/fail sufficiency language from the main claim;
- report "rank-1 approximation quality quantified" rather than "rank-1 sufficient."

- One-time weaker tolerance option:
- before the main held-out closure study, a single weaker working set may be adopted if justified by the pilot fluctuation analysis:
- `0.33 sigma` on mean shifts;
- `15%` on variance;
- `15%` on predictive score;
- this choice must be frozen once and not retuned on favorable Higgs outcomes.

- Anti-p-hacking rule:
- the metric definitions, the threshold status, and any weaker tolerance set must all be frozen before the main held-out Higgs closure study;
- continuous metrics are reported regardless of whether a binary sufficiency label is used.

- Risk:
- rank 1 may be geometrically real but not sufficient as a compressed posterior summary.
- Why acceptable:
- the paper still yields a quantitative answer about the approximation quality of low-rank transfer.
- Fallback:
- shift the scientific claim from sufficiency to a calibrated approximation boundary.

6. Minimal scientific claim

- Positive minimal claim:
- one identifiable gluon-PDF direction exists, normalized `m_tt` constrains it, and it explains a material fraction of the prior PDF variance of normalized `|y_H|`.
- Stronger claim, only if both the nuisance partition and sufficiency audit survive:
- the posterior of a low-dimensional propagated state, `z` alone or `(z, c)` if promotion is required, is an adequate summary of the Higgs posterior change induced by top data.
- Negative claim:
- if the geometry gate fails, if the nuisance partition requires too much shared state, or if the sufficiency audit does not support a hard claim, then the baseline sequential rank-1 transfer picture is not validated.

7. Core subtasks

- Subtask A: overlap and observable freeze
- map the `x-Q^2` support of normalized `m_tt` and normalized `|y_H|`;
- decide whether inclusive `m_tt` is adequate or whether one minimal `|y_tt|` split is needed.
- Risk:
- the overlap may be too weak or too broad to support one interpretable mode.
- Fallback:
- quantify the overlap ceiling and treat any extra top splitting as a follow-up, not a silent baseline expansion.

- Subtask B: early absolute-vs-normalized `m_tt` geometry gate
- execute the gate before the main closure program;
- decide whether normalized `m_tt` is allowed as the baseline top observable.
- Risk:
- normalization may discard the transfer-relevant mode.
- Fallback:
- terminate or explicitly redefine the baseline rather than proceeding ambiguously.

- Subtask C: rank-1 mode extraction
- build whitened top and Higgs response matrices;
- extract the leading shared mode;
- test stability under PDF basis choice, mild rebinning, and replica fluctuations.
- Risk:
- the leading shared structure may not be stable.
- Fallback:
- publish a quantitative upper bound on low-rank transferability.

- Subtask D: nuisance inventory and promotion
- fill the nuisance inventory table;
- classify each source into `u_t`, `u_H`, or candidate `c`;
- run the promotion workflow for common candidates;
- freeze the propagated latent state as `z` or `(z, c)`.
- Risk:
- too many common nuisances may survive normalization.
- Fallback:
- downgrade the claim to a PDF-only idealization or to a low-dimensional shared-state study rather than a pure PDF-transfer study.

- Subtask E: `ttbar` identifiability closure
- infer the posterior on the frozen propagated state from top pseudo-data;
- quantify bias, calibration, contraction, and mode learnability.
- Risk:
- the mode may exist geometrically but be too weak to infer robustly from top data.
- Fallback:
- separate geometric identifiability from inferential learnability and report the gap honestly.

- Subtask F: sufficiency audit against the richer reference model
- compare the rank-1 or low-dimensional sequential posterior to the richer shared-state reference;
- decide whether sufficiency can be claimed or only approximation quality can be quantified.
- Risk:
- approximation error may remain too large for a strong compressed-summary claim.
- Fallback:
- retain only the continuous approximation metrics.

- Subtask G: sequential Higgs closure
- propagate the top posterior on the allowed latent state into normalized `|y_H|`;
- test calibration, bin-wise shifts, and uncertainty reduction on held-out pseudo-data.
- Risk:
- top learns something real but too weak to matter for Higgs.
- Fallback:
- publish a practical upper bound on the impact of `ttbar`-driven PDF transfer for this Higgs observable.

- Subtask H: realism audit
- re-run closure under expanded theory and nuisance settings;
- compare the sequential construction to a matched joint model.
- Risk:
- the transfer story may only work in a too-clean toy limit.
- Fallback:
- identify which shared nuisance families or higher-rank PDF components are responsible and formulate them as the next-stage program.

8. Staged execution plan

- Stage 0: freeze the baseline scope
- normalized `m_tt` -> normalized `|y_H|`;
- rank 1 remains the default propagated state;
- absolute `m_tt` is an early gate, not an alternate baseline;
- not in baseline paper: `pT(H)`, single-top, inclusive jets, SMEFT.
- Risk:
- the baseline may look narrow.
- Why acceptable:
- a first paper needs a hard, interpretable yes/no chain.
- Fallback:
- keep extensions as clearly labeled follow-up branches.

- Stage 1: run the early geometry gate
- compare absolute and normalized `m_tt` immediately;
- freeze whether the baseline observable is valid before any major downstream work.
- Deliverables:
- one geometry figure;
- one gate summary table;
- one explicit decision note: pass, conditional pass, or fail.
- Risk:
- gate may fail.
- Fallback:
- convert the project into an observable-choice boundary result instead of continuing under false assumptions.

- Stage 2: extract and interpret the shared PDF mode
- derive the rank-1 shared mode in the frozen observable setup;
- report variance capture and `x-Q^2` interpretation.
- Materiality benchmark:
- around one-third Higgs prior PDF variance capture is attractive for a standalone paper, but this is a benchmark, not a theorem.
- Risk:
- shared structure may be real but too weak.
- Fallback:
- publish the ceiling on transferability.

- Stage 3: operationalize the nuisance partition
- complete the nuisance inventory;
- run candidate-common response scans;
- freeze whether the propagated state is `z` or `(z, c)`.
- Deliverables:
- nuisance inventory table;
- promotion summary;
- statement of which common blocks are propagated, stress-tested, or excluded.
- Risk:
- shared nuisances may materially compete with the PDF mode.
- Fallback:
- either promote them honestly or narrow the claim.

- Stage 4: `ttbar` identifiability closure
- infer the latent state from top pseudo-data under the frozen nuisance partition;
- quantify learnability and calibration.
- Risk:
- geometry may not translate into inference.
- Fallback:
- downgrade to a geometry-only result plus a no-go inference statement.

- Stage 5: threshold hardening and sufficiency audit
- run pilot fluctuation studies to determine whether sufficiency thresholds are decision rules or screening tolerances;
- freeze the status of the thresholds;
- compare the compressed model to the richer reference model.
- Deliverables:
- threshold-status note: hard decision rules or provisional screening tolerances;
- continuous approximation metric table;
- optional binary sufficiency label only if justified.
- Risk:
- the thresholds may not be numerically stable enough to carry a hard claim.
- Fallback:
- remove pass/fail language and keep the quantitative comparison.

- Stage 6: sequential Higgs closure
- propagate the top posterior on the frozen latent state into Higgs;
- measure calibration and uncertainty reduction on held-out pseudo-data.
- Impact benchmark:
- `10-20%` Higgs-variance reduction is attractive but not required;
- even smaller, well-calibrated transfer is publishable if the interpretation is clean.
- Risk:
- the net Higgs gain may be small.
- Fallback:
- present a calibrated practical ceiling rather than oversell sensitivity.

- Stage 7: realism audit under expanded settings
- test whether the central conclusion survives richer nuisance and theory structure;
- compare to a matched joint construction to expose hidden factorization failures.
- Risk:
- the result may only survive in an idealized setup.
- Fallback:
- turn that into a precise boundary statement and a roadmap for rank-2/shared-state follow-up.

9. Concrete synergy and follow-up branches

- Follow-up branch A: one minimal `|y_tt|` split
- Belongs because it sharpens `x` overlap without changing the basic top-to-Higgs transfer logic.
- Trigger:
- only if Stage 1 or Stage 2 shows inclusive `m_tt` overlap is too diluted.

- Follow-up branch B: extend the propagated state from `z` to `(z, c)`
- Belongs because the nuisance partition may reveal that a tiny common non-PDF block is required for honesty.
- Trigger:
- only if the promotion workflow shows one or two common nuisance families materially compete with the PDF mode.

- Follow-up branch C: additional control channels such as single-top or inclusive jets
- Belongs because they can help triangulate gluon and quark directions after the baseline is understood.
- Trigger:
- only after the baseline paper establishes whether even the simplest sequential transfer works.

- Follow-up branch D: SMEFT contamination study
- Belongs because new-physics deformations can masquerade as PDF structure in top and Higgs observables.
- Trigger:
- only after the baseline transfer geometry and nuisance logic are stabilized.

10. Explicit validity criteria

- V1: pre-definition
- the observable definitions, whitening prescription, mode-extraction method, nuisance inventory format, promotion workflow, and threshold status are all frozen before the main held-out Higgs closure study.

- V2: geometry survival
- normalized `m_tt` survives the early absolute-vs-normalized gate strongly enough to justify the baseline, or the baseline is explicitly downgraded or terminated.

- V3: operational partition
- every important nuisance source is assigned to `u_t`, `u_H`, or `c`, with a recorded action and a response-based justification.

- V4: inferential learnability
- the frozen propagated latent state is identifiable from top pseudo-data with acceptable calibration and bias.

- V5: honest threshold semantics
- the sufficiency thresholds are either validated as stable decision rules or explicitly labeled as provisional screening tolerances.

- V6: compressed-transfer credibility
- the final claim matches what survived:
- `z` only, if the baseline remains clean;
- `(z, c)`, if a low-dimensional common nuisance block is required;
- approximation-quality only, if hard sufficiency is not justified;
- no-go boundary, if the geometry or nuisance logic fails.
