1. Core thesis

Use CMS dileptonic ttbar data to constrain a frozen, low-dimensional latent description of the gluon PDF, then propagate that same latent description into one frozen first Higgs observable: the ggF Higgs rapidity spectrum `d sigma / d |y_H|` in a fiducial CMS measurement.

The proposal stands or falls on one adversarial claim:
- at least one frozen gluon direction must be identifiable in detector-level ttbar after realistic nuisance profiling, and
- that same direction must induce a quantitatively resolvable effect in the frozen Higgs target.

No Higgs precision-improvement claim is allowed before those two conditions are met with pre-declared metrics.

2. Frozen first target and frozen basis-construction recipe

Frozen first Higgs target
- Use exactly one first target: ggF Higgs rapidity, binned in `|y_H|`, with 4 bins over `0 <= |y_H| <= 2.5`.
- Do not start with inclusive Higgs combinations, `pT_H`, or double-differential observables.
- Reason: Higgs rapidity is directly tied to incoming parton `x`, is less exposed than `pT_H` to recoil-model details, and is realistic for a first CMS transfer study.

Frozen basis-construction recipe
- Freeze the prior family to one Hessian PDF set, used consistently for both ttbar and Higgs response studies. No basis redesign is allowed after detector-level fits begin.
- Freeze the perturbative setup used for basis construction: one generator chain, one central scale choice, and one nominal top/Higgs modeling setup.
- Define the overlap support window once from truth-level event samples:
- for ttbar, accumulate the `(x1, x2, Q)` support for dileptonic CMS-acceptance events;
- for ggF Higgs, accumulate the same support for the chosen `|y_H|` bins;
- convert both to a one-dimensional effective gluon-luminosity support in `log x` using the nominal process weights;
- define the overlap window as the contiguous `log x` interval containing 90% of the common support weight of the two processes.
- Build the response matrix `R` before any detector-level work:
- columns: all PDF eigenvector variations of the frozen Hessian set;
- rows: fractional shifts of the ttbar truth summaries and the 4 Higgs rapidity bins;
- use only observables defined before any detector-level optimization.
- Restrict `R` to the overlap window by weighting each eigenvector response with the common-support kernel defined above.
- Construct the latent basis operationally:
- normalize each eigenvector-response column to unit norm in the weighted observable metric;
- perform SVD on the weighted response matrix;
- retain the first two right-singular directions as the latent basis candidates;
- map them back into PDF-eigenvector space and orthonormalize them with respect to the Hessian metric;
- define these two frozen directions as `g1` and `g2`.
- Retention rule:
- keep `g1` only if it explains at least 35% of the weighted response variance;
- keep `g2` only if the first two directions together explain at least 60% and `g2` alone explains at least 15%;
- otherwise collapse Milestone 1 to a 1-direction basis.
- Freeze the published basis package:
- PDF family and version,
- generator setup,
- overlap-window definition,
- observable list used in `R`,
- the explicit linear coefficients of `g1` and `g2` in eigenvector space,
- the expected truth-level shifts induced in ttbar and Higgs observables.

Why this belongs in the plan
- It prevents basis shopping after the detector-level study starts.
- It ensures the latent directions are defined by joint ttbar-Higgs transfer relevance, not just by what ttbar alone measures easily.

3. Main work packages

WP1. Truth-level overlap map and frozen basis package
- Produce the truth-level overlap map in `log x` and `Q`.
- Build and lock the basis package exactly once using the recipe above.
- Publish a transfer table giving the induced fractional shift from `+1 sigma` in each retained direction for:
- each ttbar truth summary used to motivate detector observables;
- each Higgs `|y_H|` bin.
- Deliverable: a frozen basis package that is not changed during Milestone 1.
- Main risk: the overlap support is too weak or fragmented to support two useful directions.
- Why acceptable: this is an early physical falsification point, not a technical setback.
- Fallback: reduce to a single retained direction; if even that fails the retention rule, stop the top-to-Higgs program for this target.

WP2. Detector-level ttbar inference with realistic nuisance structure
- Build the top-only inference on a fixed detector-level observable set:
- lepton `eta`,
- dilepton rapidity,
- dilepton `pT`,
- `mll`,
- leading and subleading b-jet `eta`,
- jet multiplicity,
- `HT`,
- recoil-sensitive event summary.
- Fix the nuisance menu before optimization:
- detector response and calibration,
- backgrounds and normalization systematics,
- renormalization/factorization-scale variations,
- ISR/FSR,
- shower/hadronization model,
- color reconnection,
- top-`pT` modeling,
- MC statistical uncertainty.
- Train or fit only on this frozen observable set and nuisance menu.
- Output:
- posterior/profile constraints on each retained `gk`,
- nuisance-response matrix in the same observable space,
- closure-test results for injected `gk` shifts.
- Main risk: nuisance directions span the same response subspace as the latent PDF directions.
- Why acceptable: if so, the transfer claim is not credible and should fail here.
- Fallback: keep only the single best-separated direction if it still passes the frozen metrics below.

WP3. Hard-gated identifiability test with frozen metrics

Milestone 1 is a numerical gate, not a narrative judgment. The following metrics are frozen before detector-level fitting.

Metric A. Prior-to-posterior contraction
- For each retained direction `gk`, define `Ck = sigma_post(gk) / sigma_prior(gk)`.
- Pass threshold: at least one retained direction must satisfy `Ck <= 0.75`.
- Strong-pass threshold: `Ck <= 0.60`.
- Failure: no retained direction satisfies `Ck <= 0.75`.

Metric B. Alignment against nuisance span
- For each retained `gk`, compute the cosine overlap between its detector-level response vector and the linear span of the frozen nuisance responses:
- `Ak = ||P_nuis r(gk)|| / ||r(gk)||`, where `P_nuis` projects onto the nuisance span.
- Pass threshold: at least one retained direction must satisfy `Ak <= 0.85`.
- Strong-pass threshold: `Ak <= 0.75`.
- Failure: all retained directions have `Ak > 0.85`.

Metric C. Closure under injected shifts
- Inject `+1 sigma` and `-1 sigma` shifts for each retained `gk` into pseudo-data.
- Refit with the full nuisance model.
- Define normalized bias `Bk = |mu_hat - mu_true| / sigma_post`.
- Pass threshold: for at least one retained direction, median `Bk <= 0.25` and 95th-percentile `Bk <= 0.50`.
- Failure: no retained direction meets both bounds.

Metric D. Transfer size into Higgs
- For each retained direction, propagate a `+1 sigma` shift to the 4-bin Higgs rapidity spectrum after nuisance propagation.
- Define `Tk = max_i |Delta_i(gk)| / sigma_H,i`, where `sigma_H,i` is the expected total uncertainty in Higgs bin `i` under the baseline external-PDF treatment.
- Pass threshold: at least one retained direction must satisfy `Tk >= 0.50`.
- Strong-pass threshold: `Tk >= 1.00`.
- Consistency-only threshold: `0.25 <= Tk < 0.50`.
- Failure: all retained directions have `Tk < 0.25`.

Metric E. Propagated Higgs coverage
- Run top-only fits on injected pseudo-data, propagate the fitted latent parameters to Higgs, and test coverage on the 4 Higgs bins.
- Pass threshold: 68% intervals must cover in 60%-76% of pseudo-experiments for every Higgs bin used in the transfer claim.
- Failure: any claimed Higgs-transfer bin falls outside that coverage band.

Allowed Milestone 1 outcomes
- Pass:
- at least one retained direction satisfies Metrics A, B, C, D, and E at the pass thresholds;
- this unlocks a Higgs propagation study with an uncertainty-reduction claim.
- Partial pass:
- at least one retained direction satisfies A, B, C, and E, but only the consistency-only threshold in D (`0.25 <= Tk < 0.50`);
- this does not unlock any uncertainty-reduction claim;
- it only permits a Higgs consistency-test result: top-informed proton-structure constraints are propagated to Higgs and tested for compatibility, with no claim that CMS has materially reduced Higgs PDF uncertainty.
- Fail:
- no retained direction satisfies the full logical conditions above;
- the program stops or retargets, and no Higgs propagation paper is framed as an in-situ calibration result.

Decision rule
- No qualitative override is allowed.
- If the frozen metrics say `Fail`, the outcome is `Fail` even if qualitative plots look promising.
- If the frozen metrics say `Partial pass`, the wording is restricted to consistency testing.

WP4. Sequential Higgs propagation, only after the gate
- Only after `Pass` or `Partial pass`, propagate the retained top-constrained latent directions into the frozen Higgs rapidity likelihood.
- Required outputs:
- baseline Higgs uncertainty decomposition under external PDF treatment;
- Higgs result with top-constrained latent directions;
- explicit statement of whether the outcome is:
- uncertainty-reduction mode (`Pass` only), or
- consistency-test-only mode (`Partial pass` only).
- In `Partial pass`, prohibit the following claims:
- “PDF uncertainty reduced,”
- “in-situ calibration achieved,”
- any quoted effective Higgs precision gain beyond statistical fluctuation studies.
- In `Partial pass`, allow only:
- compatibility test between top-informed latent proton structure and Higgs data,
- evaluation of whether Higgs data disfavor the top-inferred latent shift.
- Main risk: the gain in Higgs precision is smaller than expected.
- Why acceptable: the gate structure makes even a no-gain consistency result scientifically interpretable.
- Fallback: if the outcome is `Partial pass`, publish the transfer as a cross-process proton-structure consistency test and stop there for this target.

WP5. Later extensions, only after a clean first target
- Allow extension to coarse `(y_H, pT_H)` only after a full `Pass` on the first target.
- Allow a simultaneous top-plus-Higgs likelihood only after sequential propagation has been demonstrated stably.
- Re-run the same basis-locking and frozen-metric gate for every new target; no extension inherits approval automatically.
- Main risk: scope creep weakens the claim.
- Why acceptable: the plan makes every expansion re-earn credibility under the same adversarial rules.
- Fallback: freeze expansion until the first target yields a clear `Pass` or publishable `Partial pass`.

4. Staged plan

Near-term: 0-9 months
- Freeze the Higgs target, prior family, generator setup, observable list, and overlap-window procedure.
- Produce truth-level overlap maps and the frozen basis package.
- Implement detector-level ttbar inference with the full nuisance menu.
- Run injected-signal closure and nuisance-alignment studies against the frozen metrics.

Mid-term: 9-18 months
- Complete Milestone 1 and classify the outcome strictly as `Pass`, `Partial pass`, or `Fail`.
- If `Pass`, run sequential Higgs propagation and quantify the allowed uncertainty reduction.
- If `Partial pass`, run only the Higgs consistency-test analysis.
- If `Fail`, document whether failure arose from poor contraction, nuisance alignment, closure bias, weak transfer, or Higgs coverage failure.

Later-stage: 18+ months
- Only after a `Pass`, extend to coarse `(y_H, pT_H)` or a simultaneous fit.
- Reuse the same adversarial workflow: frozen target, frozen basis, frozen metrics, then propagation.

5. Risk assessment and fallback logic

Risk 1. Top-modeling degeneracy dominates the detector-level response
- Main risk: apparent PDF sensitivity is mostly nuisance-aligned.
- Why acceptable: the program is explicitly designed to test this adversarially.
- Fallback: keep only one retained direction if it still satisfies Metrics A-C; otherwise stop.

Risk 2. Transfer to Higgs is too small to support calibration
- Main risk: top learns a direction that barely moves the Higgs target.
- Why acceptable: this is a real physical no-transfer result, not a failed analysis.
- Fallback: downgrade to `Partial pass` only if `Tk` is in the frozen consistency-only window; otherwise fail and retarget later.

Risk 3. Basis instability across theory choices
- Main risk: `g1,g2` change materially under reasonable PDF-family or generator alternatives.
- Why acceptable: a non-robust basis should not be used for a transfer claim.
- Fallback: document the instability and collapse to a single conservative direction, but only as a new stage with a newly frozen recipe.

Risk 4. Higgs-side improvement is real but small
- Main risk: even a clean `Pass` yields modest practical precision gain.
- Why acceptable: demonstrating a valid shared latent proton-structure inference is already scientifically distinct from standard external-PDF treatment.
- Fallback: emphasize validated transfer and consistency logic, not headline precision.

Risk 5. Scope drift blurs the proposal
- Main risk: extra channels or observables are added before the first target is settled.
- Why acceptable: the plan already blocks this procedurally.
- Fallback: no new target can start until the first target has a closed Milestone 1 classification.

6. What would count as success

Minimum success
- One frozen latent gluon direction passes Metrics A-E for the Higgs rapidity target.
- CMS can then make a defensible statement that part of the Higgs PDF uncertainty is internally constrained by ttbar data for this specific observable.

Intermediate success
- Milestone 1 reaches only `Partial pass`.
- CMS can still make a scientifically useful statement that top-informed proton-structure constraints are transferable enough to support a Higgs consistency test, but not enough to claim meaningful in-situ uncertainty reduction.

Strong success
- One retained direction meets the strong-pass thresholds for contraction, nuisance separation, and transfer size.
- Sequential propagation yields a measurable reduction in the PDF-driven component of the Higgs rapidity uncertainty while preserving Higgs-bin coverage.

High-payoff success
- The first-target workflow passes cleanly enough that the same locked-down methodology can be re-used for a broader Higgs observable or a simultaneous top-plus-Higgs fit without losing identifiability.

7. Why this version is sharper

The plan is now operational in the parts that matter most:
- the first Higgs target is frozen;
- the basis-construction recipe is explicit and locked;
- the Milestone 1 gate is numerical rather than qualitative;
- `Partial pass` is constrained to a strict consistency-test-only outcome.

That makes the proposal harder to game, easier to execute, and more scientifically honest about what the top-to-Higgs bridge has actually earned.
